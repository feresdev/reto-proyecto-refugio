# Constitución del backend

## Objetivo

Construir una API REST para el sistema de gestión del refugio de animales. El backend permitirá autenticar al administrador y gestionar el registro y consulta de animales.

## Tecnologías

- TypeScript sobre Node.js.
- Hono.js para la capa HTTP.
- PostgreSQL como base de datos.
- `pg` para la conexión con PostgreSQL.
- JWT para autenticación.
- `jose` para firmar y verificar JWT.
- `bcrypt` con 8 rondas para las contraseñas.
- Zod para validación de entradas.
- Variables de entorno mediante `dotenv`.

No se implementará una lista negra ni revocación de JWT en el backend. Al cerrar sesión, el cliente eliminará el token.

## Arquitectura

Se utilizará una arquitectura de tres capas:

1. **HTTP/presentación:** rutas, controladores y middlewares.
2. **Servicios:** reglas de negocio y coordinación de operaciones.
3. **Persistencia:** repositorios y consultas parametrizadas a PostgreSQL.

```text
src/
├── config/
├── controllers/
├── middlewares/
├── repositories/
├── routes/
├── schemas/
├── services/
└── types/
```

## Entidades

### Administrador

- `Identificador`
- `Usuario`
- `Contrasena`

### Animal

- `Identificador`
- `Nombre`
- `Raza`
- `Edad`
- `Sexo`
- `FechaIngreso`
- `TipoAnimal`

## Reglas de negocio

- El usuario tiene un máximo de 15 caracteres.
- La contraseña tiene un máximo de 60 caracteres.
- Las contraseñas nuevas se almacenan con bcrypt y 8 rondas.
- `Sexo` solo admite `Hembra` o `Macho`.
- `TipoAnimal` solo admite `Perro` o `Gato`.
- `FechaIngreso` es asignada automáticamente por PostgreSQL.
- Las operaciones sobre animales requieren un JWT válido.
- El cierre de sesión elimina el JWT en el cliente; el backend no persiste tokens revocados.

## Endpoints

| Método | Ruta | Autenticación | Función |
| --- | --- | ---: | --- |
| POST | `/auth/login` | No | Iniciar sesión |
| POST | `/auth/logout` | No | Confirmar cierre de sesión del cliente |
| POST | `/animals` | Sí | Registrar un animal |
| PUT | `/animals/:id` | Sí | Actualizar un animal |
| GET | `/animals` | Sí | Listar animales |

Los filtros de `GET /animals` son opcionales y se pueden combinar: `nombre`, `raza`, `sexo` y `tipoAnimal`.

## Fases de implementación

### Fase 1: Inicialización

- Configurar Node.js, TypeScript y Hono.
- Configurar variables de entorno.
- Crear el punto de entrada de la aplicación.

### Fase 2: Persistencia

- Configurar el pool de PostgreSQL.
- Implementar repositorios de administradores y animales.
- Usar consultas parametrizadas.

### Fase 3: Validación y seguridad

- Crear esquemas Zod.
- Configurar bcrypt con 8 rondas.
- Crear generación y verificación de JWT.
- Crear middleware de autenticación.

### Fase 4: Autenticación

- Implementar inicio de sesión.
- Implementar cierre de sesión sin revocación en servidor.
- El administrador inicial se carga con un hash bcrypt de 8 rondas.

### Fase 5: Gestión de animales

- Implementar registro.
- Implementar actualización.
- Implementar listado general.
- Implementar listado filtrado.

### Fase 6: Integración

- Registrar rutas y middlewares.
- Manejar errores HTTP.
- Verificar conexión entre autenticación, PostgreSQL y operaciones de animales.

No se incluyen tareas de pruebas automatizadas ni documentación de API.
